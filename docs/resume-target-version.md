## 项目经历

### 秒杀商城测试开发实践

**项目类型：** Java 电商/高并发秒杀系统  
**项目技术：** Spring Boot 3、MyBatis-Plus、MySQL 8、Redis、Lua、JWT、RabbitMQ、Redisson、JUnit 5、Mockito、MockMvc、pytest、requests

**项目描述：** 参与一个包含用户、商品、管理员、普通订单、支付退款和秒杀活动的商城后端测试开发实践。系统使用 JWT + Redis 完成认证，使用 Redis 预扣库存和异步队列处理秒杀请求，并通过订单状态机、乐观锁和唯一索引保证交易数据一致性。

**主要工作：**

1. 阅读 Controller、DTO、Service、Mapper 和全局异常处理代码，梳理接口参数、业务码、权限要求、订单状态和库存变化，建立用户、商品、管理员、订单和秒杀测试范围。
2. 使用 JUnit 5、Mockito 编写 Service 单元测试，覆盖登录失败、重复注册、商品不存在、缓存命中/未命中、库存不足、订单取消回滚、支付回调幂等、秒杀库存扣减和消息失败回滚等场景。
3. 使用 MockMvc 编写 Controller 测试，验证正常响应、缺少参数、参数类型错误、业务异常、JSON 返回结构和 HTTP 状态码。
4. 使用配置单元测试验证管理员拦截路径，覆盖 `/admin/**` 和 `/product/admin/**`；发现商品管理路径未配置管理员拦截后补充配置并完成回归。
5. 发现 `page=abc` 在参数绑定失败时被通用异常处理器错误返回 HTTP 500，补充 `MethodArgumentTypeMismatchException` 处理，使接口返回 HTTP 400 和业务码 `2001`。
6. 使用 curl 完成真实接口测试，覆盖注册、登录、错误密码、手机号格式错误、用户名/手机号重复、未登录、无效 Token、退出后 Token 失效和管理员权限矩阵。
7. 使用 pytest + requests 构建接口自动化测试，采用 `conftest.py` 管理基础地址、普通用户账号、管理员账号、Token 和 HTTP Session；使用参数化复用登录字段校验场景。
8. 针对 Redis 中同一用户新登录会覆盖旧 Token 的特性，将易失的 Token/Session fixture 设置为函数级隔离，解决完整回归中的 `Token 已过期` 偶发失败。
9. 验证普通订单链路：创建订单、查询详情、取消订单、重复取消、数量边界、商品不存在和订单不存在；检查订单状态从待支付到已取消的变化以及库存回滚。
10. 验证支付状态机：待支付订单支付成功、支付后订单详情更新、相同支付流水号重复回调幂等成功、不同流水号回调被拒绝。
11. 补充退款和超时关单测试，验证已支付订单退款、重复退款幂等、未支付订单超时关闭、库存回补和订单状态最终一致。[待完成]
12. 补充秒杀功能测试，覆盖活动未开始、活动已结束、库存不足、重复秒杀、限购、频率限制、异步下单结果轮询和失败回滚。[待完成]
13. 使用 JMeter 或 wrk 执行秒杀接口并发测试，记录吞吐量、平均响应时间、P95/P99、错误率，并使用 SQL 校验订单数、库存数和重复下单情况。[待完成]
14. 配置 GitHub Actions 或 Jenkins，在提交后自动执行 Maven 测试、pytest 接口测试和测试报告归档。[待完成]
