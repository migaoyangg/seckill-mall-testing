### 移动端自动化测试平台

**个人项目 | 2026.XX - 至今**

#### 项目背景

面向 Android App 的自动化测试平台。平台独立于商城业务系统，通过管理 APK、Android 设备、测试用例和执行任务，完成移动端 UI 自动化测试、测试数据留存和报告生成。以商城 Android App 作为首个被测应用，商城后端保持不变。

#### 技术栈

`Spring Boot`、`MySQL`、`Redis`、`Python`、`pytest`、`Appium 2`、`UiAutomator2`、`ADB`、`Android`、`Kotlin`、`Docker`、`Jenkins`、`Allure`

#### 主要工作

- 负责移动端自动化测试平台的整体设计，拆分平台 API、任务调度、设备管理、测试执行和报告归档等模块。
- 设计测试平台数据模型，支持测试项目、被测 App、APK 版本、测试用例、测试步骤、测试套件、标签和执行记录管理。
- 设计测试任务状态机，区分待执行、排队中、执行中、通过、失败、取消和超时状态，保证任务结果可追溯。
- 开发 APK 上传和版本管理能力，保存包名、版本号、文件校验值、上传人和上传时间，并校验 APK 与测试项目的归属关系。
- 开发 Android 设备管理能力，通过 ADB 获取设备序列号、型号、Android 版本和连接状态，实现设备注册、心跳、占用和释放。
- 开发独立测试执行 Worker，由 Worker 接收任务、安装 APK、启动 Appium Server、执行 pytest 用例并回传状态。
- 使用 Redis 或消息队列实现测试任务异步调度，通过设备分布式锁避免同一设备被多个任务同时占用。
- 增加任务超时、异常释放、失败重试和取消处理，避免设备长期处于占用状态或任务永久卡住。
- 自动采集 Appium 日志、pytest 标准输出、设备 Logcat、关键步骤截图和失败现场信息，并关联到执行记录。
- 集成 Allure 生成测试报告，展示用例通过率、失败步骤、执行耗时、错误堆栈、截图和历史执行结果。
- 接入 Jenkins 流水线，实现提交代码后构建 Android APK、安装到模拟器、执行移动端回归测试和归档报告。
- 使用 Docker Compose 管理平台后端、Redis、数据库和执行服务，编写环境搭建、任务排查和设备故障处理文档。
- 使用 Kotlin 开发商城 Android 客户端作为被测应用，使用 Retrofit 对接已有商城接口，并设置稳定的资源 ID 便于自动化定位。
- 使用 Python、pytest、Appium 2 和 UiAutomator2 编写登录、商品浏览、商品详情、创建订单、订单查询和退出登录用例。
- 对接口测试与 UI 测试分层：接口测试验证业务和数据，UI 测试验证页面交互和端到端用户流程。
