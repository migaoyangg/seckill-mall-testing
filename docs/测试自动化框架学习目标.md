# 两个项目的学习目标

## 总目标

围绕同一个秒杀商城完成两个方向：项目一建设后端测试自动化框架，项目二建设 Android 自动化测试平台。两个项目共用商城后端，但测试对象、架构和最终产出不同。

## 项目一：后端测试自动化框架

- Java 分层测试：JUnit 5、Mockito、MockMvc。
- Python 接口自动化框架：pytest、requests、fixture、参数化、Session、Token 管理。
- 接口业务覆盖：用户、商品、管理员、订单、支付、退款和秒杀。
- 数据校验：HTTP 状态码、业务码、响应 JSON、MySQL 数据和 Redis 状态。
- 测试配置与报告：多环境配置、Allure/HTML 报告、失败重跑和 CI 执行。

项目一最终简历定位：`秒杀商城后端测试自动化框架`。

## 项目二：Android 自动化测试平台

- Android UI 自动化执行：Appium、pytest、Page Object、显式等待、截图和日志。
- 平台能力：测试用例、测试任务、Android 设备、执行记录和报告管理。
- 执行能力：APK 安装/清理、设备连接、任务执行、失败重试和结果归档。
- 后续扩展：Allure、Jenkins/GitHub Actions、多设备执行和平台接口。

项目二最终简历定位：`秒杀商城 Android 客户端自动化测试平台`。

## 学习顺序

1. 完成支付重复请求、支付回调幂等和退款接口测试。
2. 完成超时关单、秒杀边界和异常场景测试。
3. 增加 SQL/Redis 数据一致性校验和测试数据清理。
4. 学习 JMeter 或 wrk，完成基础并发测试并记录真实结果。
5. 接入 Jenkins 或 GitHub Actions，自动执行 Maven 和 pytest 回归。
6. 在 Android App 上使用 Appium + pytest 搭建 Page Object 执行框架。
7. 增加 Android 平台的用例、任务、设备、报告和执行记录管理能力。
8. 增加截图、日志、失败重试、多环境配置和 CI。

## 简历定位

项目一名称使用：`秒杀商城后端测试自动化框架`。

项目二名称使用：`秒杀商城 Android 客户端自动化测试平台（建设中）`。

只有已经实现并验证的功能才能写入简历；项目一不写测试平台能力，项目二的平台能力完成后再删除“建设中”。
