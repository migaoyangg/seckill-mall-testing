# 开源项目对标与后续演进

## 对标项目

| 项目 | 可借鉴能力 | 本项目当前状态 |
| --- | --- | --- |
| [macrozheng/mall](https://github.com/macrozheng/mall) | 商品、购物车、优惠券、收货地址、订单后台、前后端分离运营能力 | 已覆盖商品、订单、支付、管理员基础能力；购物车、营销和地址体系待补 |
| [macrozheng/mall-swarm](https://github.com/macrozheng/mall-swarm) | 微服务拆分、网关、认证中心、分布式部署 | 当前是单体应用，适合先完成领域边界，再按流量拆分 |
| [doocs/advanced-java](https://github.com/doocs/advanced-java) | 秒杀、库存、限流、消息可靠性和一致性实践 | 已落地 Redis Lua、异步队列、MySQL 乐观锁和回滚；监控、消息重试告警待补 |

## 本轮已落地

- 首页改为运营型商城：商品搜索、分类筛选、排序、商品详情、数量下单、活动入口和统计概览。
- 秒杀前端区分“请求已受理”和“订单创建成功”，按 requestId 轮询结果，失败时展示可重试状态。
- 订单中心支持状态筛选、支付、取消、退款，管理员视图支持商品上下架、活动创建、订单发货。
- 页面使用响应式布局，覆盖手机、平板和桌面宽度；产品图片使用商品主图并提供失败回退。
- 秒杀结果查询绑定用户，避免不同用户通过 requestId 查看他人结果。
- 普通订单数量增加正数校验；支付流水号绑定其他订单时返回明确业务错误。

## 建议的下一阶段

1. 交易域：购物车、收货地址、订单收货信息、订单完成和售后单。
2. 营销域：优惠券、满减、会员价、秒杀预约和开售提醒。
3. 运营域：商品编辑、活动编辑/下线、用户搜索、订单导出、操作审计。
4. 工程化：OpenAPI 前端 SDK、统一错误码、Redis/RabbitMQ 监控、消息重试死信告警、Prometheus 指标。
5. 安全性：支付回调改为签名校验，重要操作增加幂等键和审计日志；补充 requestId 越权、库存回滚和支付竞争的自动化测试。
6. 架构演进：当商品读流量和秒杀流量明显增长后，再拆出商品服务、交易服务和秒杀服务，避免过早微服务化。
