# 秒杀入口性能测试记录（2026-09-22）

## 测试结论

本轮使用 JMeter 对单机开发环境的秒杀入口执行 100 用户瞬时并发测试。100 个请求均通过 HTTP 状态与业务受理双重断言，异步订单全部落库，未发生超卖、重复用户订单或队列积压。

## 环境与场景

| 项目 | 实测配置 |
| --- | --- |
| 测试机 | Apple A18 Pro，8 GB，macOS 26.6.2 |
| 部署方式 | 应用、JMeter、MySQL、Redis运行于同一台测试机 |
| 异步模式 | Redis队列 |
| 压测工具 | Apache JMeter 5.6.3，非GUI模式 |
| 场景 | `POST /api/seckill/do/{id}` |
| 并发用户 | 100个不同用户Token |
| 线程/Ramp-up/循环 | 100 / 1秒 / 1次 |
| 活动初始库存 | 100 |

## 测试过程发现与修正

首次执行时，原JMeter计划只断言HTTP 200。由于商城业务异常也使用HTTP 200返回，过期Token被误统计成“0%错误”，但订单数和库存均未变化。随后为计划增加业务码 `200` 和状态 `PROCESSING` 双重响应断言，刷新100个用户Token并重新执行；本文件仅记录修正后的有效结果。

原始证据位于本地 `target/performance/`：

- `seckill-entry-100-valid.jtl`
- `report-seckill-entry-100-valid/index.html`
- `report-seckill-entry-100-valid/statistics.json`

`target/` 默认不提交版本库，投递或演示前应将HTML报告作为CI制品或单独归档。
