## 项目一：秒杀商城后端测试自动化框架

**项目简介：** 基于 Spring Boot 的电商秒杀系统，包含用户、商品、管理员、订单、支付退款和秒杀模块；使用 MySQL、Redis、JWT、Lua、消息队列和乐观锁处理认证、库存及订单一致性。
**技术栈：** Java、Spring Boot 3、MyBatis-Plus、MySQL、Redis、JWT、RabbitMQ、Redisson、JUnit 5、Mockito、MockMvc、pytest、requests、curl、JMeter/wrk

**工作内容：**

- 梳理 Controller/Service/DTO 接口、参数校验、权限规则、业务码和订单状态机，设计正常、异常、边界、越权、幂等和状态流转用例。
- 使用 JUnit 5、Mockito、MockMvc 编写 Service/Controller 自动化测试，覆盖用户、商品、管理员、订单、支付回调和秒杀核心分支。
- 使用 pytest + requests 编写真实接口自动化，利用 fixture 管理普通用户/管理员账号、Token 和 Session，使用参数化复用参数校验场景。
- 使用 curl 验证注册登录、JWT + Redis 鉴权、管理员权限、订单创建/取消/支付、重复支付回调和错误参数场景。
- 定位并修复参数类型异常返回 HTTP 500、管理员路径漏拦截、Token fixture 复用导致的测试不稳定等问题，并完成回归验证。
- [待完成] 补充退款、超时关单、秒杀未开始/已结束/售罄/重复秒杀/限购/限流/异步结果轮询和失败回滚测试。
- [待完成] 使用 JMeter/wrk 执行并发测试，结合 SQL 校验订单数、库存数、重复下单和 Redis/MySQL 数据一致性。
- [待完成] 接入 Jenkins/GitHub Actions，自动执行 Maven、pytest 回归并归档测试报告。

## 使用原则

- 第一项目可以现在写已完成的 Java、pytest、curl、权限、订单和支付内容。
- 退款、秒杀、并发、SQL 一致性和 CI 完成后，再删除对应的 `[待完成]` 或 `[待实测]`。
- 第二项目当前客户端 MVP 已存在，但自动化测试平台尚未完成；完成用例、任务、设备、执行和报告闭环后，再删除“建设中”。
- 项目一目标是完成可复用的后端测试自动化框架；项目二继续以 Android 自动化测试平台为目标。
- 不要编造并发数、P95、通过率、兼容设备数或缺陷数量。
