## 移动端自动化测试平台（旧版）

**项目类型：个人项目｜项目时间：2026.XX - 2026.XX｜技术栈：Spring Boot、Python、pytest、Appium 2、UiAutomator2、ADB、MySQL、Redis、Jenkins、Allure、Docker**

### 项目背景

针对 Android 商城 App 的登录、商品浏览、下单和订单查询等核心流程，独立设计并开发移动端自动化测试平台，解决人工回归耗时长、测试结果难追溯、设备资源冲突和失败现场缺失等问题。商城后端保持不变，Android 商城 App 作为首个被测应用。

### 项目内容

- 设计平台分层架构，拆分项目/App 版本、APK 管理、测试用例、测试任务、Android 设备、执行 Worker 和测试报告模块。
- 开发 APK 上传与版本管理、测试用例/套件管理、任务创建和执行记录接口，支持包名、版本号、文件校验值、执行设备和任务状态关联。
- 基于 ADB 实现设备注册、心跳检测、设备状态查询、APK 安装/卸载和设备释放；使用设备锁避免同一设备被多个任务同时占用。
- 开发测试执行 Worker，负责接收任务、启动 Appium Server、调用 pytest + UiAutomator2 执行用例，并回传排队、执行、通过、失败、超时和取消状态。
- 使用 Redis/消息队列实现异步任务调度，增加任务超时、失败重试、异常设备释放和任务取消处理，避免任务长期阻塞。
- 自动采集 Appium 日志、pytest 输出、Android Logcat、步骤截图和失败现场，统一关联到测试执行记录。
- 集成 Allure 和 Jenkins，实现 Android APK 构建、模拟器安装、移动端回归执行和测试报告归档。
- 为商城 App 编写登录、错误密码、商品列表、商品详情、创建订单、订单查询和退出登录等 UI 自动化用例，并与接口测试分层。
