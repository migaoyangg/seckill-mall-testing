# 软件测试总体流程

本文档用于记录本项目从测试准备到上线后的总体测试流程。内容保持在流程和阶段目标层面，具体测试用例另行维护。

## 1. 了解项目需求

阅读需求文档、产品说明和接口文档，了解系统要解决的问题、主要用户角色、业务规则以及预期结果。针对本项目，重点了解用户、商品、秒杀、订单、支付和管理员等业务流程。

## 2. 分析系统架构和测试重点

了解系统的技术架构、模块划分、服务之间的调用关系以及数据流转过程，识别可能影响系统质量的关键环节。重点关注 Redis、MySQL、异步消息、库存扣减、订单状态和权限认证等部分。

## 3. 制定测试计划和测试范围

明确测试目标、测试内容、测试优先级、测试人员、测试时间和交付物，同时确定哪些内容本轮测试，哪些内容暂不覆盖，并制定测试通过标准。

## 4. 搭建测试环境和准备测试数据

准备应用运行所需的数据库、中间件、配置和测试工具，保证测试环境可以稳定运行。根据业务场景准备管理员、普通用户、商品、不同状态的秒杀活动和不同状态的订单等测试数据。

## 5. 设计测试用例

根据需求和风险分析结果设计测试用例，覆盖正常流程、异常流程、边界条件、权限控制和数据校验。为重要业务流程补充前置条件、操作步骤、预期结果和数据检查项。

## 6. 执行基础验证和功能测试

先验证项目能够正常编译、启动和连接依赖服务，再按照模块执行功能测试，确认各个接口和页面能够完成预期业务。测试内容包括用户、商品、秒杀、订单、支付和管理员功能。

## 7. 执行接口、异常和安全测试

检查接口的请求参数、响应内容、错误提示和状态码，验证非法参数、重复请求、未登录访问、无效令牌、越权操作等场景，确认系统能够正确拒绝异常请求并保护数据安全。

## 8. 执行核心业务流程测试

按照真实用户操作串联多个模块，验证从登录、浏览商品、参与秒杀、异步下单、支付到订单处理的完整链路。同时检查库存、订单状态、支付结果和用户操作之间是否保持一致。

## 9. 执行性能、并发和稳定性测试

使用性能测试工具模拟不同并发量和持续时间，观察系统的响应时间、吞吐量、错误率以及资源使用情况。重点验证秒杀入口、库存扣减、异步下单、结果查询和订单处理在高并发下是否稳定。

## 10. 记录、跟踪并验证缺陷

发现问题后记录复现条件、操作步骤、实际结果、预期结果、日志和相关数据，评估缺陷影响范围和优先级。开发修复后重新执行原测试，并检查修复是否引入新的问题。

## 11. 执行回归测试

在缺陷修复、功能变更或配置调整后，重新验证受影响功能及其关联功能，确保原有功能没有发生回退。对库存、订单状态、消息处理和权限等关键模块进行重点回归。

## 12. 输出测试报告并进行上线评估

汇总测试范围、环境、执行结果、缺陷情况、遗留风险和性能数据，根据发布标准判断系统是否具备上线条件。对于未完成或存在风险的内容，应明确记录并得到相关人员确认。

## 13. 上线后监控和问题跟踪

上线后关注接口错误率、响应时间、库存数据、订单状态、消息堆积、支付回调和系统资源等运行指标。发现线上问题后及时记录、定位、修复并安排后续回归验证。

## 总体顺序

```text
了解需求
→ 分析架构和风险
→ 制定测试计划
→ 准备环境和数据
→ 设计测试用例
→ 基础验证和功能测试
→ 接口、异常和安全测试
→ 核心流程测试
→ 性能、并发和稳定性测试
→ 缺陷跟踪与验证
→ 回归测试
→ 测试报告和上线评估
→ 上线后监控
```
