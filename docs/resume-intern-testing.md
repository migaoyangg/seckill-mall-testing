项目描述：基于 Spring Boot 的商城后端，包含用户、商品、管理员、订单和秒杀等模块；围绕认证、权限、库存和订单状态开展测试开发实践。

个人工作：

- 使用 JUnit 5、Mockito 编写 Service 单元测试，覆盖用户登录、商品查询、普通订单、支付回调、秒杀预扣库存和库存同步等业务场景。

- 发现 `page=abc` 被通用异常处理器错误返回 HTTP 500 的问题，补充 `MethodArgumentTypeMismatchException` 处理，使接口返回 HTTP 400 和业务码 `2001`。
- 发现 `/product/admin/**` 未被管理员拦截器覆盖的问题，补充拦截路径并增加配置测试，验证 `/admin/**` 和 `/product/admin/**` 均受管理员权限保护。

- 使用 Python pytest + requests 重写接口自动化测试，采用 fixture 管理基础地址、普通用户 Token、管理员 Token 和 HTTP Session。
- 使用参数化测试复用登录必填参数校验逻辑，并使用独立 Token fixture 解决 Redis 中新登录 Token 覆盖旧 Token导致测试不稳定的问题。
- 使用真实接口验证管理员权限矩阵：未登录返回 `1001`、普通用户返回 `1002`、管理员正常返回 `200`。
- 验证普通订单链路：创建订单、查询订单详情、取消订单、重复取消拦截；覆盖待支付 `0`、已取消 `4` 和订单状态错误 `3005`。

## 三、面试时可以讲的测试思路

1. 先按 Controller 梳理接口、参数和鉴权要求。
2. 再按 Service 识别正常、异常、边界、幂等和状态流转场景。
3. 用 Mockito 隔离依赖验证业务分支和副作用。
4. 用 MockMvc 验证 Controller、异常处理和权限结果。
5. 用 curl/pytest 验证真实 HTTP 行为。
6. 对会修改数据的流程记录订单号、商品 ID 和前后状态，测试后检查数据是否恢复或符合预期。
