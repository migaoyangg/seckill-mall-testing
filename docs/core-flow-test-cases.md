# 核心流程功能与异常测试用例

本文档面向发布前功能回归和接口异常验证，覆盖登录鉴权、商品管理、秒杀下单、支付回调、退款、取消及超时关单。用例按当前接口实现编写，业务错误通常为 HTTP 200 + `code`，参数校验为 HTTP 400 + `code=2001`。

## 1. 测试约定

基础地址：`http://127.0.0.1:8080/api`。准备管理员 `admin`、普通用户 `testuser` 和用户 B；秒杀活动至少准备“未开始、进行中（库存 1）、已结束”三条数据。每次用例使用独立商品/活动或记录前后库存，避免历史订单影响唯一索引 `uk_user_seckill_goods`。

通用校验：响应 `code/message/data`；数据库订单状态、支付流水号、支付/退款时间；普通商品库存或秒杀库存；Redis token、订单超时 key、秒杀结果和限购标记。订单状态：`0`待支付、`1`已支付、`4`已取消、`5`超时关闭、`6`退款中、`7`已退款。

| 业务码 | 含义 | 业务码 | 含义 |
| --- | --- | --- | --- |
| 1001 | 未登录 | 1002 | 无权限 |
| 1003 | Token 无效 | 1004 | Token 已过期/已退出 |
| 1005 | 账号禁用 | 1006 | 用户名或密码错误 |
| 2001 | 参数错误 | 3002 | 商品/活动不存在 |
| 3003 | 商品已下架 | 3004 | 订单/秒杀结果不存在 |
| 3005 | 订单状态异常 | 4001/4002 | 秒杀未开始/已结束 |
| 4003 | 秒杀库存不足 | 4004/4005 | 重复秒杀/超出限购 |
| 4006 | 秒杀失败或限流 | 5001 | 普通库存不足 |

## 2. 登录与鉴权

| 用例ID | 类型 | 接口/前置条件 | 步骤 | 预期 |
| --- | --- | --- | --- | --- |
| AUTH-F-001 | 功能 | `POST /user/login`，正常用户 | 提交正确用户名密码 | HTTP 200，`code=200`，返回非空 JWT；Redis 保存 `user:token:{userId}`；用户角色正确 |
| AUTH-F-002 | 功能 | 管理员账号 | 登录并访问 `GET /admin/order/list` | 登录成功，管理接口 `code=200` |
| AUTH-F-003 | 功能 | 已登录 | `GET /user/info` | 返回当前用户信息，不包含密码；userId 与 token 对应 |
| AUTH-F-004 | 功能 | 已登录 | `POST /user/logout` 后再次访问 `/user/info` | 退出 `code=200`；Redis token 删除；旧 token 返回 `1004` |
| AUTH-E-001 | 异常 | 无 token | 访问 `/user/info`、`/order/create`、`/seckill/do/{id}` | 返回 `1001`，不产生订单、不扣库存 |
| AUTH-E-002 | 异常 | token 字符串错误或 JWT 签名错误 | `Authorization: Bearer invalid` | 返回 `1003` |
| AUTH-E-003 | 异常 | JWT 有效但 Redis token 不存在/已被另一设备登录覆盖 | 携旧 token 请求受保护接口 | 返回 `1004`，不进入业务方法 |
| AUTH-E-004 | 异常 | 数据库中账号 `status=0` | 尝试登录 | 返回 `1005`，不生成 token |
| AUTH-E-005 | 异常 | 用户名不存在或密码错误 | 登录 | 返回 `1006`，不泄露“用户不存在/密码错误”的差异信息 |
| AUTH-E-006 | 异常 | 普通用户 token | 访问任一 `/admin/**` 或 `/product/admin/**` | 返回 `1002`，数据不变 |
| AUTH-E-007 | 异常 | 缺少 `Bearer ` 前缀、空 Bearer、大小写错误 | 访问受保护接口 | 返回 `1001` 或 `1003`，按约定统一且不放行 |
| AUTH-E-008 | 异常 | 登录/注册必填字段为空、密码长度越界 | 提交 JSON | HTTP 400，`code=2001`，数据库无脏数据 |

## 3. 商品管理

| 用例ID | 类型 | 接口/前置条件 | 步骤 | 预期 |
| --- | --- | --- | --- | --- |
| PROD-F-001 | 功能 | `GET /product/list` | 默认分页、分类、品牌、价格区间及排序各执行一次 | HTTP 200；分页正确；用户侧只返回上架商品；筛选和排序结果准确 |
| PROD-F-002 | 功能 | `GET /product/detail/{id}`，商品存在 | 查询详情两次 | 返回商品及分类信息；第二次命中缓存；内容与数据库一致 |
| PROD-F-003 | 功能 | 管理员 token、合法 `ProductDTO` | `POST /product/admin/add` | `code=200`；商品落库、默认上架、库存/价格准确 |
| PROD-F-004 | 功能 | 管理员、商品存在 | `PUT /product/admin/update` 修改价格/库存/描述 | `code=200`；数据库更新；详情缓存失效后读到新值 |
| PROD-F-005 | 功能 | 管理员 | `PUT /product/admin/status/{id}/0`，再改回 `1` | 下架成功；用户侧列表隐藏；重新上架后可见 |
| PROD-F-006 | 功能 | 管理员 | `DELETE /product/admin/delete/{id}` | `code=200`；逻辑删除；详情/列表不再返回 |
| PROD-E-001 | 异常 | 普通用户或无 token | 新增、修改、删除、上下架 | 分别返回 `1002`/`1001`，商品不变 |
| PROD-E-002 | 异常 | 管理员 | 新增名称空、价格 `0`/负数、库存负数、分类为空；修改缺少 id | HTTP 400 + `2001`；不写库 |
| PROD-E-003 | 异常 | 管理员 | 查询/修改/删除不存在 id | 返回 `3002`（修改/删除不应创建新记录） |
| PROD-E-004 | 异常 | 商品已下架 | 普通用户 `POST /order/create?productId={id}` | 返回 `3003`；库存不扣减 |
| PROD-E-005 | 异常 | 商品库存为 0 或 quantity 大于库存 | 创建订单 | 返回 `5001`；库存不变、无订单明细 |
| PROD-E-006 | 异常 | 合法管理员 | 并发修改库存与并发下单 | 不得出现负库存；乐观锁失败请求返回库存不足/业务错误；缓存最终与数据库一致 |
| PROD-E-007 | 异常 | 任意接口 | 价格/库存传字符串、超长名称、非法分页（0 或负数） | HTTP 400 或明确参数错误；不出现 500，不写入异常值 |

## 4. 秒杀下单与异步结果

| 用例ID | 类型 | 接口/前置条件 | 步骤 | 预期 |
| --- | --- | --- | --- | --- |
| SECKILL-F-001 | 功能 | `GET /seckill/detail/{id}` | 查询活动详情及剩余库存 | 返回活动时间、折扣、状态描述；Redis 预热后剩余库存准确 |
| SECKILL-F-002 | 功能 | 进行中活动、Redis 库存充足 | 普通用户 `POST /seckill/do/{id}`，立即查 `/seckill/result/{requestId}` 并轮询 | 入口 `code=200`、状态 `PROCESSING`；最终 `SUCCESS`，订单为待支付且 `is_seckill=1`，订单号一致 |
| SECKILL-F-003 | 功能 | 管理员、合法时间和折扣 | 创建活动、开启 `status=1`、结束 `status=2` | 创建/开启成功并预热 Redis；结束时剩余库存回写 DB、Redis key 删除 |
| SECKILL-E-001 | 异常 | 无 token | 参与秒杀 | 返回 `1001`；不扣 Redis 库存 |
| SECKILL-E-002 | 异常 | 未开始活动 | 参与秒杀 | 返回 `4001`；不产生重复标记、订单和扣库存 |
| SECKILL-E-003 | 异常 | 已结束活动或 status 非进行中 | 参与秒杀 | 返回 `4002`；数据不变 |
| SECKILL-E-004 | 异常 | 活动 id 不存在 | 参与/查详情 | 返回 `3002` |
| SECKILL-E-005 | 异常 | Redis 库存为 0 | 参与秒杀 | 返回 `4003`；订单数为 0，不能出现负库存 |
| SECKILL-E-006 | 异常 | 同一用户同一活动已请求/已落单 | 连续或并发请求两次 | 后续返回 `4004` 或 `4005`；最多一笔订单和一次库存扣减 |
| SECKILL-E-007 | 异常 | 单用户 1 秒内快速请求超过限制 | 连续请求 10 次 | 返回 `4006`；不因限流造成库存泄漏；允许重试时检查标记是否正确回滚 |
| SECKILL-E-008 | 异常 | 消费者落单失败（模拟 DB/消息失败） | 入口成功后注入失败并查结果 | 结果为 `FAIL`；Redis 预扣库存、重复标记、限购标记均回滚 |
| SECKILL-E-009 | 异常 | requestId 不存在/过期 | 查询 `/seckill/result/{requestId}` | 返回 `3004`；不能查询到其他用户结果 |
| SECKILL-E-010 | 安全 | 用户 A 的 requestId | 用户 B 带自己的 token 查询 A 的结果 | 应返回 `1002`/`3004`；当前 `getSeckillResult` 未接收 userId，需将该用例作为发布阻断项验证并修复 |
| SECKILL-E-011 | 异常 | 管理员修改/删除进行中活动 | 调用更新或删除 | 返回 `2001`；活动、Redis 库存和已有订单不受影响 |
| SECKILL-E-012 | 并发 | 库存 1，用户 A/B 同时请求 | 并发 2 个入口请求并等待消费 | 最多 1 个 `PROCESSING/SUCCESS`；成功订单数不超过初始库存；`初始库存-成功订单数-剩余库存=0` |

## 5. 支付与支付回调

| 用例ID | 类型 | 接口/前置条件 | 步骤 | 预期 |
| --- | --- | --- | --- | --- |
| PAY-F-001 | 功能 | 待支付普通订单 | `POST /order/pay/{orderNo}?payType=1` | `code=200`；状态 `0->1`，写入 payType/payTime/模拟 transactionNo，删除超时 key |
| PAY-F-002 | 功能 | 待支付秒杀订单 | 使用支付接口完成支付 | 状态 `0->1`，金额等于秒杀价；不增加/回滚库存 |
| PAY-F-003 | 功能 | 待支付订单 | 回调 `POST /order/pay/callback/{orderNo}?payType=1&transactionNo=TX-001` | `code=200`；订单保存 `TX-001`，超时任务不再关闭 |
| PAY-F-004 | 幂等 | 已支付订单，原 transactionNo | 重复调用同一回调 2 次或并发 20 次 | 均成功/幂等返回；仅一条支付流水，状态保持 1 |
| PAY-E-001 | 异常 | transactionNo 为空/空白 | 调用回调 | 返回 `2001`；订单仍待支付 |
| PAY-E-002 | 异常 | 已支付订单、不同 transactionNo | 用 `TX-002` 回调 | 返回 `3005`；原流水号不被覆盖 |
| PAY-E-003 | 异常 | 订单已取消或超时关闭 | 调用 pay/payCallback | 返回 `3005`；不得恢复或扣错库存 |
| PAY-E-004 | 异常 | 订单不存在、用户 B 访问用户 A 订单 | 支付或回调 | 返回 `3004`；订单与流水号均不变 |
| PAY-E-005 | 异常/缺陷 | 同一 transactionNo 绑定订单 A 后回调订单 B | 先支付 A，再用相同流水号回调 B | B 不得被支付，A 状态不变；应返回可识别的 `3005`。当前实现可能因唯一键异常返回 HTTP 500，需记录并修复为受控业务错误 |
| PAY-E-006 | 并发 | 待支付订单 | 线程 1 回调，线程 2 同时超时关单 | 最终只能是已支付或超时关闭之一；不能出现已支付且库存已回滚/重复流水 |
| PAY-E-007 | 异常 | payType 缺失、非支持值、类型错误 | 调用支付接口 | 缺失使用默认值 1；非法类型 HTTP 400；不产生部分支付记录 |

## 6. 取消、退款与库存回滚

| 用例ID | 类型 | 接口/前置条件 | 步骤 | 预期 |
| --- | --- | --- | --- | --- |
| REFUND-F-001 | 功能 | 待支付普通订单 | `POST /order/cancel/{orderNo}` | `code=200`；状态变为 `4`；商品库存恢复 1；删除超时 key |
| REFUND-F-002 | 功能 | 已支付订单 | `POST /order/refund/{orderNo}` | 状态经历 `1->6->7`；写入 refundTime；库存仅恢复一次 |
| REFUND-F-003 | 幂等 | 已退款订单 | 重复退款 | 返回成功/幂等；状态仍为 `7`，库存不再次增加 |
| REFUND-E-001 | 异常 | 已支付订单 | 调用取消 | 返回 `3005`；库存不变 |
| REFUND-E-002 | 异常 | 待支付、已取消、超时关闭、退款中订单 | 调用退款 | 返回 `3005`（已退款订单除外）；不得回滚库存 |
| REFUND-E-003 | 异常 | 订单不存在或非本人 | 取消/退款 | 返回 `3004`；不泄露订单信息 |
| REFUND-E-004 | 并发 | 已支付订单 | 并发退款 20 次 | 最多一次进入退款并恢复库存；最终状态 `7`；无重复库存回滚 |
| REFUND-E-005 | 异常 | 模拟退款第二阶段 DB 更新失败 | 使 `1->6` 后 `6->7` 更新失败 | 事务回滚或明确处于 `6` 并可重试；不能返回成功但库存已恢复/订单仍可重复退款 |
| REFUND-E-006 | 功能 | 已支付秒杀订单 | 退款 | 秒杀 DB 与 Redis 库存各恢复 1；再次退款不重复恢复 |

## 7. 超时关单与定时任务

| 用例ID | 类型 | 前置条件/步骤 | 预期 |
| --- | --- | --- | --- |
| TIME-F-001 | 功能 | 普通待支付订单创建时间超过 15 分钟；执行 `closeTimeoutOrder` 或等待扫描 | 状态变为 `5`；普通商品库存恢复；超时 key 删除 |
| TIME-F-002 | 功能 | 秒杀待支付订单创建时间超过 5 分钟 | 状态变为 `5`；秒杀 DB 库存及 Redis 预扣库存恢复；结果/限购状态按失败处理 |
| TIME-F-003 | 边界 | 普通订单未满 15 分钟、秒杀未满 5 分钟 | 扫描不关闭，状态和库存不变 |
| TIME-F-004 | 幂等 | 对同一订单重复调用关单，或消息重复投递 | 首次关闭并回滚；后续忽略；库存只恢复一次 |
| TIME-E-001 | 异常 | 已支付、已取消、已退款订单 | 执行关单 | 保持原状态，不回滚库存、不删除无关 key |
| TIME-E-002 | 异常 | orderNo 不存在/订单明细缺失 | 执行关单 | 不抛出未处理异常；不存在订单安全忽略；明细异常记录日志并可告警 |
| TIME-E-003 | 并发 | 回调支付、用户取消、定时关单三者并发 | 同一待支付订单并发执行 | 只允许一个合法终态；不能双重回滚，订单状态与库存一致 |
| TIME-E-004 | 任务 | 启动两个应用实例同时扫描 | 观察 `schedule:order:timeout` 分布式锁 | 仅一个实例执行扫描；锁释放；另一实例不重复处理 |
| TIME-E-005 | 任务 | Redis 模式、RabbitMQ 模式各执行一次 | Redis 依赖定时扫描；RabbitMQ 消费延时消息 | 两种模式均能关单；消息重复/消费失败有日志，最终状态一致 |
| TIME-E-006 | 批处理 | 构造超过 100 笔超时订单 | 执行一次扫描后再次执行 | 单次最多处理 100 笔，无遗漏；后续扫描继续处理剩余订单 |

## 8. 流程验收与发布门禁

1. 登录鉴权：AUTH-F-001、AUTH-E-001~007 全部通过；任何未授权放行阻断发布。
2. 商品管理：PROD-F-003~006、PROD-E-002~006 通过；库存不得为负，缓存不得返回已删除/下架商品。
3. 秒杀下单：SECKILL-F-002、SECKILL-E-002~010、SECKILL-E-012 通过；成功订单数不超过初始库存，重复订单为 0。
4. 支付/退款/关单：PAY-F-003~004、PAY-E-002~006、REFUND-F-002~003、REFUND-E-004、TIME-F-001~002、TIME-E-003 通过；状态迁移和库存回滚必须幂等。
5. 数据核对 SQL：`orders` 与 `order_detail` 一一对应；支付流水号唯一；`初始库存-成功订单数-剩余库存=0`；秒杀订单 `(user_id,seckill_goods_id)` 无重复。

并发用例建议使用 JMeter 或脚本同时发起 20~1000 个请求，并区分预期业务失败（售罄、重复、限购）和 HTTP 5xx 技术失败。每次回归保留请求日志、响应、数据库快照及 Redis key 变化，便于定位消息丢失、重复消费和回滚失败。
